# mini_shell - 24120111097

## What it is
It is a mini shell that runs by speaking to the kernel directly via the **std::process** module to make system calls as processes. It does not just send commands to the actual Ubuntu shell

- It is built via **cargo build --release** then tested through **python3 selfcheck.py --project ../24120111097/mini_shell --track shell --tests tests**


## What it supports
Since it is a simple or "mini" shell, it only supports simple shell commands like cd, echo, cat, single pipes per lines alongside handling of inputs and outputs of files

## How it works
- Essentially, how it works is that first the program collects input via stdin then it keeps looping what to perform on the input based off their command as long as there is a new line, which is checked from **lines.next()**, while there are still more lines and the loop is going, if the input is empty, that iteration would be skipped onto the next line, if the input is "exit", it will terminate the program and this mini shell doesn't support multiple pipes in one line. For the execution of a file without a pipe, whatever value has been trimmed (except for exit and whitespace only), goes into the **execute_single_command()** , the if trimmed.contains('|') is used if the input contains a pipe so it has to go to it's own function (**execute_pipeline()**) that handles parsing the commands before and after the pipe. Inside execute_single_command(), we first take the command passed from main and split it via **parse_redirection()**, it splits on the basis of '>' which is all it is looking for to determine the command part of the input and the optional filename part so for instance echo hello > out.txt would be split into "echo hello" and then out.txt separately, the contents of the command itself also still have to split, which is what **parse_args()** does by splitting the words in the command portion meaning that parse_args("echo hello") would give "echo" and "hello".
- Now from here it tackles what the command would do based off the first actual word in the command determining what other action would be taken, hence we set program to be the start of artgs at index 0 so we can check what the first command is before we take action on the remaining portions of the command, for changing directories, we check if the program is "cd" then from there we check how to handle the possibilites of the cd commands structure. If correct, we set the other half of the command portion to index 1 of args (proceeding program) which in the case of cd must be the directory (stored in  dir). **set_current_dir()** changes the current directory to the new one from dir. After that **let mut command = Command::new(program);** is used to make some sort of description of whatever the first command is then appends the arguments of that command with **command.args(&args[1..]);**. If the command had '>' then it would check what the file to be created is and if it is in the correct format using the same principle as the main first loop, from there if it is correctly done, it will match Ok and **command.stdout(Stdio::from(file));** sets up the execution to create the file. The file is created immediately but the output of the contents of the file is not written to the file until **match command.status()** returns Ok.
- Lastly in **execute_pipeline()**, it follows the same setup as execute_single_command() until
it reaches the point where it needs to connect two separate commands together instead of just running one. It first parses the arguments of the first command with **parse_args(cmd1_str)**, and then for the second command it will check for any output redirection at the end using **parse_redirection(cmd2_str)** before splitting its words into args2, making sure none of the commands are empty so the shell doesn't crash on an incomplete pipe like "ls | ". It then builds the first command using **Command::new(args1[0])** with its arguments, but instead of letting it print to the screen, it uses **stdout(Stdio::piped())** so its output is captured into a memory OS pipe when .spawn() launches it in the background. From there, **child1.stdout.take().unwrap()** grabs the reading end of that pipe and passes it directly into the second commands input using **.stdin(Stdio::from(pipe_reader))** on child2_builder. Just like in execute_single_command(), if the second command had a > redirection, it creates the target file via File::create() and passes it through **child2_builder.stdout()** into that file instead of the terminal. Once **child2_builder.spawn()** launches the second command or kills child1 if the second command doesnt exist, it release the builder to close the parent shells extra pipe handle and calls **child1.wait()** and **child2.wait()** so the mini shell pauses until both of the commands have finished transferring data and executing before moving on to the next input line.
- The shell terminates when exit is inputted, errors dont stop it and any line with multiple pipes will give an error
